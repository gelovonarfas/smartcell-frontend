# CLAUDE.md — SmartCell Frontend

Читай этот файл перед любой задачей. Здесь правила, нарушение которых ломает проект.

## Что мы строим

Статический фронтенд-кит для лендинга **Face Control** и блога **Smart Age Journal** (саббренд SmartCell, клиника VIRTUS, Одеса). Это НЕ WordPress-проект: мы отдаём чистые HTML/CSS/JS, которые кодер клиента натянет на PHP-шаблоны темы `virtus`. Наша задача — стройная вёрстка с адаптивом и разметкой, удобной для переноса.

Контекст продукта — `docs/PRODUCT.md`. Дизайн-система — `docs/DESIGN.md`. Карта блоков для кодера — `docs/HANDOFF.md`.

Читай макеты через Figma MCP (`get_design_context`, `get_screenshot`), а не по скриншотам и не по памяти.

## Железные правила

1. **`assets/css/tokens.css` не редактируется.** Он сгенерирован из Figma. Нужно другое значение — сообщи мне, я поменяю переменную в Figma и перевыгружу файл. Правка токена в коде = раздвоение источника правды.
   Чего нет в выгрузке (мера строки, кривые и длительности переходов, прозрачности, шкала отступов) —
   живёт в `assets/css/base.css` под префиксом `--sc-*` и помечено как согласуемое.
2. **Только CSS-переменные.** Никаких хардкод-значений для цвета, отступа, радиуса, типографики. `padding: var(--card-p)`, не `padding: 28px`. Исключение — величины, которых нет в системе (например `1px` для hairline).
3. **Ванильный стек.** Чистый HTML + CSS + минимум JS. Никаких React, Tailwind, сборщиков, npm-зависимостей в рантайме. Кодер должен открыть файл и понять его без инструментов.
4. **BEM с префиксом `sc-`**: `.sc-journey__step`, `.sc-journey__step--active`, состояния `.sc-is-active`.
   Префикс обязателен: в теме `virtus` живут свои `column-item`, `dropdown1` — без него каскад конфликтует.
   Типографические роли тоже с префиксом: `.sc-t-h2`, `.sc-t-body`.
5. **Тёмные секции** — через `data-theme="inverse"` на секции, не через отдельные цвета.
6. **Мобильный** — один брейкпоинт (640px), значения переопределяются в `:root` внутри media query. Не пиши отдельные правила по классам для мобильного, если структура не меняется принципиально.
7. **Никогда не удаляй и не переписывай чужие секции** без явной просьбы. Работаем по одному блоку.

## Разметка под перенос в WordPress

Каждая секция начинается комментарием с якорем на Figma и списком редактируемых полей:

```html
<!-- ============================================================
     B12 · На що впливаємо (полосы показателей)
     figma: node-id=15:112
     ACF: impact_title (text), impact_rows (repeater: label, term, value, percent),
          impact_note (textarea), impact_image (image)
     ============================================================ -->
```

Тексты в вёрстке — украинские из макета, как есть. Не переводи, не сокращай, не улучшай формулировки: медицинский контент согласован с клиникой.

Мультиязычность (qTranslate-X) подключит кодер — наша задача не мешать: не склеивай текст из кусков в JS, каждая строка должна быть цельным текстовым узлом в HTML.

## Известные дефекты макета — в коде исправляем

Макет местами уступает требованиям доступности. Не копируй эти места буквально:

- **Мера строки.** В макете есть строки по 96–114 символов. В коде ограничивай прозу `max-width: var(--measure)` (65ch).
- **Контраст.** `--muted-foreground` на сером фоне даёт 4.31:1 — на светлых бэндах используй `--neutral-600` для мелкого текста.
- **Состояния.** В Figma их нет вообще. В коде обязательны: `:hover`, `:focus-visible` (через `--ring`), `:active`, `:disabled`, состояния ошибки и загрузки для форм.
- **Тексты на фото.** Всегда со скримом (`--black-alpha-40/60`), не полагайся на удачный кадр.

Правило остаётся прежним: не выдумывай новые цифры, не меняй существующие и не добавляй медицинских утверждений от себя. Всё, что появится в макетах позже и не подтверждено, снова помечается [VERIFY] до согласования.
