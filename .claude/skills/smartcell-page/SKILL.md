# Новая страница в ките SmartCell

Кит — чистые HTML, CSS и JS без сборщиков, переносится в тему `virtus` (WordPress).
Стенд для согласования: `smartcell-frontend.gelovonarfas.workers.dev`. Всё ниже —
выжимка из того, что уже сделано и проверено на пяти страницах; повторять, не изобретать.

## 0. Перед стартом

1. Прочитать `CLAUDE.md` (железные правила), `smartcell/DESIGN.md`, `docs/HANDOFF.md`.
2. Макет — только через Figma MCP, по одному фрейму за раз (`get_screenshot`,
   `get_metadata`; для `get_design_context` сначала загрузить `figma-design-to-code`).
   Файл `t3K32ifBrrW1kD2BBbp1tA`.
3. Найти похожий готовый блок в `sections/` и взять его за образец — там уже решены
   поля, отступы, состояния и мобильная раскладка.
4. Один блок = одна задача = один коммит. Следующий не начинать, пока предыдущий не принят.

## 1. Разметка секции

Файл `sections/<код>-<имя>.html`. Шапка обязательна — по ней Николай собирает шаблон:

```html
<!-- ============================================================
     B12 · На що впливаємо (полосы показателей)
     figma: node-id=15:112
     ACF: impact_title (text), impact_rows (repeater: label, term, value, percent),
          impact_note (textarea), impact_image (image)
     Решения и даты правок — сюда же, коротко.
     ============================================================ -->
<section class="sc-impact" data-impact>
```

Правила:
- BEM с префиксом: `.sc-block__element`, `.sc-block__element--mod`, состояния `.sc-is-*`.
  В журнале префикс `vm-`. Типографика ролями `.sc-t-h2`, `.sc-t-body`, `.sc-t-mini`.
- Тёмная секция — `data-theme="inverse"` на секции или на «острове» внутри неё, не цветами.
- Тексты — украинские из макета, как есть. Каждая строка — цельный текстовый узел,
  ничего не склеивать в JS (qTranslate).
- Хуки для скриптов — `data-*` атрибуты, не классы: `[data-scenario-prev]`, `[data-vm-featured-slide]`.
- Цифры и медицинские утверждения не выдумывать; новое — с пометкой `[VERIFY]`.
- Картинка: `<img>` с реальным путём, `width`/`height`, `alt` на украинском, `srcset` @1x/@2x,
  `loading="lazy"` всему, что не в первом экране. Видео — см. §4.
- Готовую секцию вставить в страницу копией с маркером
  `<!-- Секция — копия sections/x.html -->`; страница — источник правды для стенда,
  секция — для передачи. Раз в передачу сверять (скрипт сверки в истории: diff тел без комментариев).

## 2. Стили

Файл `assets/css/sections/<тот же код>.css`, подключается в `<head>` страницы.

- **`tokens.css` не править** — он из Figma. Нужен другой токен — сказать пользователю,
  он меняет в Figma и перевыгружает.
- Только переменные. Чего нет в токенах — в `base.css` под `--sc-*` (шкала отступов
  `--sc-space-*`, меры строк, длительности, кривые, альфы, `--sc-line`, `--sc-chip-pad`,
  `--sc-focus-w/offset`, `--sc-progress-h`). Литерал px допустим только для 0.5/1 px линий.
  Размер из макета одного места — локальная переменная блока с комментарием:
  `--story-cta-w: 320px; /* Button/Block в макете */`.
- Один брейкпоинт `640px`; мобильные значения переопределять в переменных блока, а не
  писать вторую раскладку. Если структура меняется принципиально (одна колонка вместо
  двух) — допускается `display: contents` и явные `grid-area`, как в B04a и VM/Featured.
- Липкие боковины на мобильном прячем (`display: none`), не липнем.
- Состояния обязательны: `:hover`, `:focus-visible` (`outline: var(--sc-focus-w) solid var(--ring); outline-offset: var(--sc-focus-offset)`), `:active`, `:disabled`, ошибка/загрузка форм.
- `prefers-reduced-motion: reduce` — у всего, что двигается, `transition: none`/`animation: none`.
- Контраст: `--muted-foreground` на светлой/синей полосе даёт < 4.5 — мелкий текст там на `--sc-neutral-600`.
- Стекло — `.is-glass` из токенов плюс уточнение в `base.css`; `backdrop-filter` только `blur`, без `saturate`.
- Фон «в тоне рампы» поверх видео/фото: слой цвета `mix-blend-mode: color` в `::after`,
  прозрачность кадра над белой подложкой — светлота; цвет кадра значения не имеет (B08).
- Сквозные правила (кромки, числовые выноски, медиа-отступы, кнопка после текста) — в `base.css`, не дублировать в секциях.

## 3. Скрипты

Файл `assets/js/<блок>.js`, IIFE, `'use strict'`, подключение `<script src defer>`.

- Данные для контента — в разметке. Скрипт читает `[data-*]`, количество берёт из DOM,
  интервалы — из CSS-переменных (`--vm-featured-interval`).
- Состояние считать от текущих координат, а не копить события (`story.js`): иначе застревает
  при возврате снизу.
- Наведение ставит на паузу только на органах управления (стрелки), не на всём блоке.
  Фокус от указателя не пауза: флаг на `pointerdown` перед `focusin`.
- `pageshow` с `persisted` — вернуть состояние после bfcache (слайдер, перелёт обложки).
- Замеры высот (`--header-h`, `--announce-h`) — пересчитывать по `fonts.ready`,
  `ResizeObserver` (держать ссылку в массиве) и `load`; в CSS давать умолчание из вёрстки.
- `IntersectionObserver` для ленивых стартов + страховка на первой прокрутке.
- Никакого GSAP-обязательного поведения: без библиотеки страница должна работать.

## 4. Медиа

- JPG, `@1x` = размер слота в макете, `@2x` = вдвое; апскейла нет. Экспорт из Figma
  `download_assets` jpg scale 1 и 2. Тяжёлые кадры дожимать `sips -Z <w> -s formatOptions 80`;
  если стало тяжелее — оставить оригинал.
- Видео: H.264, без звука, `faststart`, CRF 28–30, 25 к/с; горизонтальные 1280 по ширине,
  вертикальные 720×1280, цель ≤ 4 МБ, мобильный хиро ≤ 1,6 МБ. У каждого — постер,
  снятый из него (canvas в headless, см. §6).
- Разметка видео — **всегда** через ленивый загрузчик:

```html
<picture class="sc-x__poster">            <!-- постер под видео, LCP-элемент -->
  <source media="(max-width: 640px)" srcset="assets/img/x-poster-mob.jpg" width="720" height="1280">
  <img src="assets/img/x-poster.jpg" alt="" width="1280" height="720" fetchpriority="high" decoding="async">
</picture>
<video class="sc-x__video" autoplay muted loop playsinline width="1280" height="720" preload="metadata" tabindex="-1">
  <source data-src="assets/video/x-mob.mp4" data-media="(max-width: 640px)" type="video/mp4">
  <source data-src="assets/video/x.mp4" type="video/mp4">
</video>
```
  `assets/js/video-lazy.js` подставляет `src` после `load` (первый экран) или у вьюпорта.
  Не ставить `poster=` — мобильный кадр тогда ждёт скрипта, LCP уезжает на 2 с.
- Всё, что скрыто (`[hidden]`, модалки) — `loading="lazy"`, иначе браузер качает.
- **На длинных страницах родного `loading="lazy"` мало**: порог Chrome на медленной сети —
  2500 px, и лента карточек стартует вместе с LCP-картинкой, деля канал (блог: обложка
  ехала 11,6 с). Картинкам ниже первого экрана — `data-src`/`data-srcset` + `width/height`,
  подставляет `assets/js/img-lazy.js` за 300 px до вьюпорта. Постерам видео ниже первого
  экрана — `data-poster`, ставит `video-lazy.js` при старте. В первом экране остаются
  только LCP-картинка и мелочь вроде аватара.
- Предзагрузку соседних кадров (сценарии) — только в простое после `load` на десктопе
  и при первом касании на телефоне.

## 5. Производительность — рецепт (мобильный PSI 57 → 96)

Что дало результат, по убыванию:
1. **Видео не в первой отрисовке** (`data-src` + `video-lazy.js`), у хиро вертикальная
   мобильная версия. Постер — `<picture>` под видео, не атрибут.
2. **Критический CSS инлайном**, остальное неблокирующе: `scripts/bundle-css.py` при сборке
   `dist` минифицирует стили, кладёт список `CRITICAL[страница]` в `<style>` и грузит бандл
   через `preload` + `onload`. **Новую страницу добавить в `CRITICAL`**: tokens, base,
   шапка и то, что в первом экране.
3. Шрифт: `preconnect` к `fonts.googleapis.com` и `fonts.gstatic.com`, `preload as=style`
   на CSS шрифта — во всех страницах перед `tokens.css`. Сборка вырезает `@import` и на
   стенде ставит `display=optional`.
4. Ничего лишнего в первом экране: скрытые картинки ленивые, предзагрузки отложены.
5. Сдвиг раскладки: у видео `width/height`; высота полосы анонса задана в CSS
   (`--announce-h` с умолчанием), текст полосы в одну строку.
6. `fetchpriority="high"` только LCP-кандидатам (постер хиро, первый кадр слайдера, обложка статьи).
7. Не грузить на странице стили и скрипты блоков, которых на ней нет.

Что остаётся Николаю на проде: бандл с хешем и долгим кешем, WebP/AVIF через `<picture>`
для кадров лент, self-host шрифта с `size-adjust`, диапазон весов `wght@200..700`.

## 6. Проверки (headless-Chrome, без ручного открытия)

```bash
python3 -m http.server 8777 &          # сервер из корня проекта
# изолированный рендер секции: страница с tokens+base+css секции и fetch('/sections/x.html')
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu --hide-scrollbars \
  --window-size=1440,1000 --screenshot=out.png --virtual-time-budget=4000 http://localhost:8777/_iso.html
# замеры: страница-зонд с <iframe>, JS пишет результат в body[data-out], читаем через --dump-dom
# видео в рендере: добавить --autoplay-policy=no-user-gesture-required
```
Ловушки headless под `--virtual-time-budget`: заморожены таймеры анимаций (GSAP, CSS
transitions застывают в первом кадре — не считать дефектом), `ResizeObserver` и
`IntersectionObserver` не доставляют обновления, `scrollTo` не двигает страницу.
Для стилей сверять **вычисленные значения** источника и `dist` через зонд с двумя
iframe и `transition:none` — так поймали, что склейка CSS ничего не ломает.
Пиксели — распаковкой PNG на чистом Python (в проекте нет PIL); контраст считать по WCAG.
Lighthouse локально: `npx lighthouse <url> --form-factor=mobile --screenEmulation.mobile --throttling-method=simulate --only-categories=performance --output=json`.
PSI API анонимно — квота в день небольшая; отчёт PSI можно отрисовать headless по ссылке и вытащить текстом.

## 7. Выкладка и передача

- Стенд: `bash scripts/deploy.sh` (собирает `dist` по `.deployignore`, склеивает CSS, `wrangler deploy`).
  Кеш всего — `max-age=0, must-revalidate`; проверять прод через `?v=<timestamp>` и md5.
- Git: коммит на каждую законченную правку, пуш в `main` (CI собирает и проверяет ссылки).
  В `CHANGELOG.md` раздел `handoff-N · в работе`, каждый пункт с пометкой **файлы** /
  **разметка** / **стенд**. Передача — тег `handoff-N`, релиз с архивом собирается сам.
- В комментариях к коду — почему, с датой: «правка 2026-09-14: …». Николай читает их как документацию.

## 8. Чек-лист перед сдачей блока

- [ ] ни одного литерала цвета/отступа/шрифта в CSS; локальные размеры — переменные с комментарием
- [ ] мобильный: один брейкпоинт, липкое скрыто, кнопки во всю ширину, порядок строк проверен замером
- [ ] состояния и `reduced-motion`; контраст мелкого текста ≥ 4.5
- [ ] медиа под слот ×2, `width/height`, `lazy` вне первого экрана, видео через `data-src`
- [ ] страница добавлена в `CRITICAL` в `scripts/bundle-css.py`; в `<head>` preconnect шрифта
- [ ] нет подключений CSS/JS чужих блоков
- [ ] рендер секции и замер геометрии; вычисленные стили `dist` = исходник
